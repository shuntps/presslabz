# Security Policy

PressLabz is pre-alpha. There are no releases and nothing is running in production yet, but the reporting process is in place from the start.

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Use GitHub's private vulnerability reporting: the **Report a vulnerability** button under this repository's Security tab. It is enabled here and keeps the report private until a fix is available.

If you cannot use it, email contact@presslabz.com.

Please include what the problem is and where, how to reproduce it or a proof of concept, and the impact you believe it has.

## What to expect

Reports are reviewed and handled on a best-effort basis, as quickly as circumstances allow. No response time is guaranteed. You will be told whether the report is accepted, and credited in the advisory when a fix ships, unless you prefer otherwise.

## Supported versions

None yet. Nothing has been released, so no version receives security fixes. Once releases begin, this section will list which lines are supported.

## Scope

This policy covers the code in this repository. Third-party plugins and themes are out of scope — the plugin system does not exist yet, and when it does, sandbox escapes and capability-model bypasses will be in scope while vulnerabilities inside individual third-party plugins will not.
